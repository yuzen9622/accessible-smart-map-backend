# TGOS 資料利用研究

研究日期：2026-10-04。範圍：官方公開文件、資料集詮釋資料與目前程式碼；未申請服務、未使用 API 金鑰、未匯入資料或修改應用程式。

## 結論

TGOS 最有價值的新增用途是門牌／路口定位、既有設施地址校正，以及補充公共服務目的地。無障礙路徑品質則應優先深化已存在的人行道、路緣坡道與高程整合，查驗覆蓋、來源版本及路網連接。

主站 `https://www.tgos.tw/TGOS/Index` 本次透過 web 工具直接讀取回傳 403；以下以官方 API 文件、可讀取的官方服務描述和原供應機關資料集交叉查證。這不是登入後完整圖資目錄盤點，也不是 TGOS 查詢 API 的成功介接測試。舊 API 文件有年代較早的範例，不能以文件仍存在推論每個服務目前可用。

## 優先資料與用途

### 1. 門牌地址定位：最高新增優先度

[官方 QueryAddr 服務描述](https://addr.tgos.tw/addrws/v30/QueryAddr.asmx)列有 APPId/APIKey、EPSG:4326 輸出、完全比對、模糊比對、縣市／鄉鎮／路段等鎖定選項，並回傳 `OutMatchType`、`OutMatchCode`、標準地址與 X/Y。

建議用途：補強完整中文地址搜尋；校正福利機構等僅有地址的政府資料；發現現有來源落在錯誤行政區或距離過遠的點位。

建議先以完全比對建立候選，失敗才做有界限的模糊比對；保留比對類型及原始來源。模糊命中相鄰門牌不能當作精確命中。門牌點也不能直接當作無障礙入口。

[我的 E 政府批次服務頁](https://www.gov.tw/News_Content_2_371654)記載：會員申請審核後可使用，每日可比對一萬筆，完成後以通知及下載成果的方式交付。這是批次服務額度，不能套用成線上即時查詢 API 的額度。

### 2. 路口定位及坐標查最近門牌：高優先度

[路口定位](https://api.tgos.tw/TGOS_MAP_API/docs/site/web/CrossLocate)支援兩條道路及縣市條件；[最近鄰地址](https://api.tgos.tw/TGOS_MAP_API/docs/site/web/PointAddr)可把坐標轉成附近門牌。

建議用途：處理「忠孝東路與復興南路口」式的語音目的地；讓障礙通報附上人可理解的位置描述。通報原始坐標必須保留，不能用附近門牌坐標覆寫。路口點也不能代表某一個可過街的角落。

### 3. 公共服務地標：補完整性，中高優先度

[TGOS 申請與授權表](https://api.tgos.tw/TGOS_MAP_API/docs/site/web/Application)列出醫療院所、社會福利服務機構、避難收容處所、警消、學校等一般圖資；[地標分類查詢](https://api.tgos.tw/TGOS_MAP_API/docs/site/web/PoiNear)有醫療社服、生活機能、交通運輸等分類。

建議用途：補充目的地搜尋與附近可求助地點，與現有福利、校園、Google、OSM 記錄比對去重。分類不代表有無障礙入口、廁所或可用電梯；這些屬性沒有證據時應維持 unknown。避難收容處所名錄也不代表此刻已開設。

### 4. 人行道與坡道：路徑品質優先，但多屬既有資料深化

[國土管理署人行道資料](https://data.gov.tw/dataset/58791)列有 202606 資源，以及側別 `SW_DIRECT`、寬度 `SW_WTH`、淨寬 `SWW_WTH`、路緣斜坡數 `SW_RAMP`。官方允許 `SW_RAMP=N` 表示無須設置，不能一律解讀為數值零。

此為原供應機關開放資料，不宣稱本次已在 TGOS 主站完成該圖層的現行目錄查證。專案已有上述資料的評估及建圖程式，後續價值在擴大地理覆蓋、更新來源與檢查對位，而非再次下載即宣稱新增能力。

[臺北市無障礙斜坡道](https://data.taipei/dataset/detail?id=8ab0c662-b560-4310-a825-001ae7fdc524)亦已在專案匯入來源中。須保留道路側別、兩端過街節點與入口連接的語意；一個人行道面記載有坡道，不代表每個路口均可無階梯通行。

本次額外實讀[官方 JSON](https://data.taipei/api/dataset/8ab0c662-b560-4310-a825-001ae7fdc524/resource/ee522d94-daa7-4118-b52a-4bf144af2744/download)：curl 正常 TLS 驗證下載成功、Python JSON 解析得到 34,684 個 features，每筆 properties 只有 `OBJECTID`、`Name`、`Town_N`、`X_3826`、`Y_3826`。雖然目錄列有 `Slope` 和 `SW_WTH`，實際檔案這兩欄存在筆數均為 0。因此此來源目前不能補足坡道坡度或寬度；34,684 也是原始 feature 數，不能當作篩選後可用無障礙坡道數。

### 5. 20 公尺 DTM：有條件更新與擴大覆蓋

[既有 20m DTM 官方資料集](https://data.gov.tw/dataset/35430)提供高程與平面坐標，並連到 TGOS 詮釋資料。[2026 年版](https://data.gov.tw/dataset/178729)於 2026-09-30 上架，官方明示各圖號產製年度不同，用途為地形起伏展示與概略分析。

注意：2026 頁面標題為 DTM，但資源顯示名稱寫 DSM。下載與升級前須核對實際產品、圖幅年份、坐標系統及高程基準，不能假定全臺均為 2026 年新測。

建議用於較長道路的地形坡度與年長者步行負擔；20m 網格不能解析路緣高度、短坡道或局部橫坡。橋梁、高架及地下道也需個別處理。專案已有 DEM 輸入程式；應驗證資料確實載入且 unknown 比例降低，而非僅看 build 成功。

### 6. 災害潛勢、行政區界與底圖：次要補強

[官方授權表](https://api.tgos.tw/TGOS_MAP_API/docs/site/web/Application)有行政區界、土石流潛勢溪流與部分災害圖資，但權限層級不同。

建議用途：行政區歸屬與資料缺口統計；沿路風險背景提示；人工檢核道路位置。潛勢圖不能當作即時積淹水或封路訊息；未搭配事件資料前，不宜直接用來封鎖路線。

## 延伸原始來源：不是本次已核實的 TGOS 圖層清單

- [環境部全國公廁建檔 FAC_P_07](https://data.moenv.gov.tw/dataset/detail/FAC_P_07)：官方列月更新，本次頁面顯示最後更新 2026-10-01；含建檔編號、名稱、坐標、類型及管理單位。可對照現有廁所 CSV 做更新與去重，但須先核實類型字典才能判定無障礙，不能把全國公廁全量標為無障礙。
- [輪行臺北](https://wheelroute.gov.taipei/)：官方圖台有可行／勉強可行／不可行，以及人行道、騎樓、行穿線、出入口、電梯等項目。適合列為人工對照與洽詢候選；本次未確認批次下載、再利用授權或資料更新機制，尚不能列為可直接匯入來源。

## 技術與授權邊界

- [主題地圖文件](https://api.tgos.tw/TGOS_MAP_API/docs/site/web/ThemeMap)明示回傳可為透明底圖片；可顯示不等於可取得向量幾何。
- [WFS 文件](https://api.tgos.tw/TGOS_MAP_API/docs/site/web/WFSLayer)描述圖徵資料存取，但平台支援 WFS 不代表每個圖層都有 WFS。路徑運算須逐圖層確認向量／屬性下載、授權及更新。
- [MAP API 申請說明](https://api.tgos.tw/TGOS_MAP_API/docs/site/web/Application)區分一般、進階、內部、防救災應用，並有 Domain/IP 驗證。公開應用、後端介接、行動 App、快取及再散布條件須對應具體服務確認，不能只依免費申請推定無限制。
- [路徑規劃文件](https://api.tgos.tw/TGOS_MAP_API/docs/site/web/Route)描述以行車距離／時間等成本規劃；沒有本次可核實的輪椅、人行淨寬、電梯狀態或公共運輸整合契約。不建議據此取代現有 OTP／步行引擎。
- 圖資匯入須記錄供應機關、原始 ID、資料日期、下載時間、坐標系統、授權與品質狀態。來源衝突需可追溯；未知不能填為可通行。

## 建議導入順序與驗收

1. 門牌離線對照：挑選建議 100–200 筆完整地址，涵蓋巷弄、之號、同名道路與既有失敗案例。比較完全命中率、錯誤行政區率、位置誤差及模糊命中比例，再決定是否接入即時搜尋。此樣本數為建議，並非已完成實驗。
2. 人行道／坡道覆蓋稽核：盤點部署建圖使用版本，量測有效淨寬已知比例、坡道兩端匹配、道路側別錯配與入口可達性，分輪椅、年長者及一般模式驗收。
3. 公共服務 POI：先新增目前缺少類別，保留供應機關 ID 並去重，不透過地點類別推論無障礙。
4. 高程更新：釐清 2026 DTM/DSM 名稱衝突後，對照舊版抽樣驗證丘陵、平地、橋梁與地下道；不把 20m 地形估計描述為坡道實測。
5. 災害與底圖：先作資訊展示與品質檢核，再評估有無足夠證據影響排序。

本次未量測 TGOS 實際定位精度、查詢延遲、付費／配額帳戶權限及生產資料覆蓋，因此不宣稱準確度已提升或資料已接入。
